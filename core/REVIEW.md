## Cold review — the reviewer payload contract
**Cold review (T1+).** A fresh agent gets **the change itself** + the spec **as a contract to falsify** (never the case for *why* it's right) + invariants + **claimed tier** — **never the author's advocacy** ('what we verified', 'gates passed', 'N cases pinned') and never the build conversation. The question is *"where does the code violate the contract — and where is the contract itself (any backstop it names) wrong or unprovable?"*, not *"is the design's argument sound?"* The **contract** = the design's **mechanism** (what it does) + acceptance criteria + invariants + the **mitigation-claims table** — *not* its **rationale** ("why it's safe"), which is **redacted from the free-adversary pass** (released only to a later folded pass). Every **semantic rule/definition** in the contract carries its own **provenance** (authoritative source · forbidden counterexamples · raw-truth fixtures): **acceptance criteria cannot define away an invariant**, and the **free adversary must judge whether the contract itself is sourced and true** — a wrong contract faithfully implemented still ships the bug (no machine catches this; it is judgment). Mandate: *try to break it; **accept nothing as true without verifying it against the code/source** — every claimed mitigation, backstop, and contract premise is a hypothesis you confirm or refute, never a fact you inherit; default FAIL on uncertainty; flag if it looks higher-risk than its claimed tier.* ⚠ **RULE #1 governs what BLOCKS, never what you may report** (`core/FOUNDATIONS.md` § Principles): **a finding that blocks must name the harm — to the Owner/user, to the usability of the product, or to the FUNCTIONALITY of the code — and the mechanism that reaches it; a finding naming none is returned as a NOTE.** **Report everything you find anyway: the DISPOSITION applies the threshold, not the seat.** A seat that silently drops what it judges harmless has deleted the finding instead of noting it, and nobody downstream can tell the two apart — **under-reporting is the failure mode this rule creates, and it is worse than a nit.** Verdict = per-dimension PASS/FAIL + evidence + the exact line; **any FAIL ⇒ overall NO-GO.** Dimensions: correctness · provenance-exactness · reversibility/blast-radius · failure-mode safety · **deploy-order safety** (code — *including the mechanical gate itself* — must not assume a migration / column / flag created by a step that runs *after* the auto-deploy; guard or flag-gate it) · **contract/additive safety** (a tool's output shape stays additive — never break a connector) · **IO** (when a deterministic/cheaper layer feeds a higher-intelligence consumer: it must surface/verify, not decide-for or limit) · **mitigation integrity** (every "safe because Y" claim has a *risk-isomorphic* canary + a backstop-disabled control — see the invariant; a generic canary proves nothing; unproven ⇒ FAIL). **Panel** = **1 free-roaming adversary (owns no dimension)** + angle-assigned reviewers (≥2 T2 / ≥3 T3) covering the dimension set; verdict artifact + payload manifest (named per `core/BINDINGS.md`) for T2/T3. **Shift-left (additive):** cold-check *proposed* designs/code *before* building, and any critical work at any tier (live-path · chain/stateful · corpus-touching · held below full certainty) — feeds the mandated panel, never replaces it, never lowers a tier. Cold reviewers run at **peer tier** (never below the Builder, so a blind peer's FAIL is a legitimate flag, not a lower-layer veto; a *disputed* FAIL → frontier-PM adjudication per Gate states) and do **not** consume the external gate.

**No unproven universals.** Every *"all X updated / N items / nothing deleted"* claim in a contract is
proven by a command **before** it is written — an unverified universal is a token bomb the PM lights
itself. **Packet composition — what the payload must carry, and must not.** The reviewer receives **the
diff itself**, the pre-change text of anything deleted, and the **outputs** of commands it would
otherwise have to predict against — a reviewer holds no shell, so an unshipped `git show` is an
unanswerable question, and a seat left to excavate the change spends its round re-deriving what could
have been handed over. The packet **excludes append-only review artifacts** (a review log): a diff
containing one ships prior verdicts to a seat that must not see them. ⚠ **AND A PACKET THAT SHIPS
COMMIT BODIES SHIPS THE REVIEW HISTORY — build the diff with `git diff`, never `git log -p`.** This
is the failure mode the subject-vs-body discipline CREATES: once findings are deliberately moved out
of subjects and into bodies, the bodies are where every measurement, verdict and residual lives, so
one convenience flag hands a seat the entire record at the last step and defeats the control that
put them there. **The SUBJECT is injected and the BODY is not — that asymmetry only holds while the
packet respects it.** **At a design gate the spec IS
the artifact** (§ Cross-family lens, artifact-mode (a)), so a spec narrating its own review history
folds every seat that reads it — ship a redacted contract with no round narration. **A filename
blocklist is not exclusion; only packet CONTENTS are** — a seat's own `grep` defeats a blocklist, so
what leaks is governed by what you send, never by what you ask it not to read. **The packet MUST carry
every new or changed file in full** — a diffstat is not a diff, and `git diff` omits untracked files,
so a seat handed one can only inherit the claim it was seated to test. **Do not answer a leak risk by
taking the seat's tools away:** a tool-less seat cannot reach `.gitignore` or any file it excludes,
and in the changeset that first proposed that rule both BLOCKERs were reachable only with tools.
Removing them trades a bounded leak for an unbounded blind spot, and contradicts this section's own
mandate to verify everything against the source.

**Rerun the gate whose input changed.** Design review, implementation review, deployment,
activation, and live proof are separate gates. Material code or contract changes rerun their own
review; wording-only clarification does not restart a full design review. Report each result in
plain language a technically literate reader can follow, and never use one gate as proof of another.

## Decorrelation — where coverage actually comes from
**Decorrelation — where coverage actually comes from.** Reviewer *count* and model *family* add **no coverage if they share the framing input**: correlated framing yields confident-wrong clears (a mitigation seven reviewers believed and none ran). Decorrelate in priority order — **(1) posture [highest]:** ≥1 **free-roaming adversary** whose payload is *exactly* the code + the **redacted contract** (mechanics + criteria + invariants + mitigation-claims table) — **no prior findings, no verdicts, no rationale** — told *"break it any way; the contract's claims are hypotheses to falsify, including any backstop it names."* No assigned angle. **(2) model family:** a different-family lens — counts only if its input is *also* unframed (run the cross-family tool **without** the folded-findings payload for this pass). **(3) angle [coverage]:** angle-assigned reviewers own distinct hunt-classes (correctness · concurrency · provenance/contract · failure-mode · security · deploy-order · **mitigation-integrity**), each unframed. **Two passes:** a free/blind pass (no prior findings) **then** a folded-delta pass (may receive prior findings, to hunt the gaps). The free adversary is **additive and owns no dimension**; the angle-assigned reviewers (≥2 T2 / ≥3 T3) cover the dimensions between them. **Enforcement — Owner spot-check, not machinery.** The verdict **records what each reviewer was given** {role · family · files · pass-type · **pre-loaded**} and which pass was the **free/unframed** one; a T2/T3/chain verdict is **NO-GO** unless a free pass is named. **`pre-loaded` is what reached the seat that nobody sent it** — harness-injected repository memory, recent commit subjects, prior findings or verdicts. **It is REQUIRED, and `no exposure` must be written explicitly when there is none, because an omitted field and a clean one are indistinguishable** — silence would be read as the reassuring answer. *"I cannot distinguish pre-loaded content from my prompt"* is an acceptable and useful entry; a seat that cannot enumerate its own inputs must at least be **asked**. ⚠ **This field is a LOG, never a certification: it records what arrived, not whether the seat was independent.** *Measured 2026-08-12: a seat holding `tools: []`, proven at zero tool calls against a paired control, still received a memory index of prior findings and a snapshot of recent commit subjects. **What you SEND is governed by packet discipline; what a seat RECEIVES is not**, so a pass is DECLARED with its known injections named and never CERTIFIED unframed.* Because reviewers self-report posture, the **Owner spot-checks the free pass** (was it really given no prior findings/advocacy?) and the mitigation verdicts — that human check is the verifier, not a hash, **and `pre-loaded` is the field that gives it something to check.** A **single-reviewer gate** (T1, or a core-doc amendment that nothing follows — `core/WORKFLOW.md` § Steer splits the row; text an implementer builds from is a T2 panel) defaults to the free-roaming posture + a mandatory mitigation-integrity check, and **that seat is CROSS-FAMILY by default** — the same seat count, the same wall-clock and the same cost, for decorrelation the tier otherwise has none of. The Builder may keep a same-family seat **only** where live full-repo depth genuinely beats independence (a subtle refactor in dense surrounding code), **records which it chose and why**, and **the escape is unavailable on any `core/` file except the recorded required-review availability route below** — a controlling document's single-reviewer gate is cross-family by default because its blast radius is every change made under it; that route records its reduced same-family-only receipt. **Accepted, named gap:** a single-seat tier is the least-decorrelated rung in the ladder; where it runs same-family it has *no* decorrelation at all. It is accepted because T1's blast radius is nil — never because the seat is sufficient, and **"T1 passed" must never be read as "T1 was decorrelated".** **The residual only the free adversary defends against is contract OMISSION.** Every other seat is pointed at something that EXISTS — an angle-assigned reviewer hunts its dimension in the text, a checker matches a spelling, the folded pass hunts the gaps in *prior findings*. A clause the contract never wrote has no line to review, no spelling to match and no finding to fold, so it is invisible to all of them; only a seat told *"the contract's claims are hypotheses, including any backstop it names"* is positioned to ask what the contract failed to promise at all. That is why the free adversary is **additive and owns no dimension** — owning one would point it at something that exists — and why a T2/T3/chain verdict is NO-GO without a named free pass. **Pass-types** are canonical + manifest-recorded: `free` forbids prior-findings/rationale/folded text; `folded` allows them. The **free adversary owns no dimension but may raise a FAIL on any**; that FAIL stops the reviewer pass and must appear in the PM disposition record, but it does not predetermine the disposition. *Foggy-multi-angle is the failure; clear-vision-first is the fix.*

**Panel WEIGHT scales to residual risk; the FLOOR never does.** The counts above (≥2 T2 / ≥3 T3 angle-assigned + the free adversary), the cross-family requirement the tier sets, AND an angle covering every dimension the candidate's OWN changes implicate (a continuation's repair delta is new unreviewed code — the angle it touches is FLOOR, reviewed this round, never dropped) are FLOOR — never the droppable "mixed-fleet" excess: the panel meets that floor EVERY round, and outside the recorded availability route, dropping below the tier's cross-family mandate (§ Cross-family lens) is a floor breach escalated to Owner; that route records same-family-only, never full. A round still carrying real unresolved harm may ALSO carry weight above the floor — a wider roster, extra angles, more families than the mandate compels — and only that EXCESS scales down: an **R1→R2 continuation whose REVIEWED residual has demonstrably collapsed** (its prior panel's accepted findings resolved, what remains peripheral and contained) precommits the floor, not the inflated roster it carried when the risk was live. **Two things are never "collapsed residual," and treating either as one is the seat cut RULE #1 forbids:** (a) code **no panel has yet reviewed** — an R3 root replacement, simplification, or split has zero accepted findings because it has had zero review, which is absence of review, not absence of risk; the **terminal R4 bookend and any root-replacement candidate ALWAYS receive the full precommitted panel** — the changeset's complete RISK-LIVE seat set (the roster bound while the risk was live, not any later-reduced one), run whole and never reduced to the floor (`core/WORKFLOW.md` § Gate Final-gate rule + the controller's `panel_open` complete expected seat set); (b) a clean budget-free pass **or the builder's own kill-pass / RED-GREEN result** — pre-panel assurances by a correlated seat, never a measurement of the residual the panel must still find (a passed free rung never lightens the panel — § Steer rung-order rule 2). It **never runs below the floor**: "prior rounds went well" is not a reason to under-run the mandate (§ Gate enumerate-rungs); a floor breach is the gate-ran-lighter carve-out. The seats that catch harm STAY — RULE #1's "cutting seats is the misreading" protects THIS floor, the review DEPTH; excess above it is neither that depth nor a seat that catches harm, and only that excess, on a continuation whose reviewed residual truly collapsed, is dropped — where an adversarial panel that never runs out of findings buys refutations, not safety. **The builder's kill-pass has a different job:** before a candidate is frozen for `panel_open`, a rigorous local self-attack + the focused RED/GREEN controls make the panel the independent check on a candidate already broken-against — it strengthens the candidate, it never lightens the panel that reviews it.

**The RECOMMENDATION carries an emitted `ACTION-SCREEN`, with the teeth `pass-type` has.** Just as a T2/T3/chain verdict is NO-GO without a named free pass, **a NO-GO / successor / continuation / added-control is VOID without its `ACTION-SCREEN`** — the field the emission line reserves (`core/WORKFLOW.md` § Gate). It is RULE #1 applied to the recommended ACTION, not only the findings (`core/FOUNDATIONS.md`): the screen is **evidence-bound** — cite the located defect in the candidate *as-shipped*, or route it (a trigger that FIRES on the candidate forbids DEFER) — so its absence is a visible empty slot, not a silent omission the Owner must ask about.

## Cross-family lens — review the ARTIFACT, not just a diff
**Cross-family lens — review the ARTIFACT, not just a diff.** A different model **family** reviews the change, run in **two passes** (per Decorrelation): a **free/blind pass** fed only the redacted contract + invariants (**no** prior findings — for posture-decorrelation), then optionally a **folded pass** fed the **prior same-family findings** to hunt the gaps the panel left. Either pass uses one of two artifact-modes: (a) **DESIGN gate** — the **design/spec doc itself is the artifact**; (b) **CODE gate** — the **diff + the design/acceptance context + the changed code files** (each up to a ~120KB per-file cap; larger files fall back to diff hunks, untracked only under ~300KB) — **but those are assembly limits, not an ingestion budget: a code-mode cross-family run is an ESCAPE bounded by the transport's inline envelope or an approved slice plan (`core/GATES.md` § Routing), because an oversized payload under-reads.** Read-only; never touches the live service. Value = **decorrelated blind spots**. **Lesson (load-bearing):** at a *design* gate — or on a docs-only changeset — a diff-only lens at most grades a tracked doc diff (the wrong lens) and finds **nothing** useful ("docs only, SAFE"); feeding the design as the artifact has caught real issues a same-family panel missed. That diff-only miss is **payload starvation, not the model** — at a design gate, feed the design. Fires with the multi-agent panel (T2/T3 + chain/stateful) as a **STANDING pre-authorized step** — a read-only cold-panel gate needs **no per-gate and no per-thread Owner authorization** to run or to transmit its payload (the frozen candidate + the redacted contract + invariants + design context; standard exclusions apply — secrets, live data, anything outside the reviewed artifact), so a session runs it as a normal step of the ladder and **never stops to ask**; availability is **discovered by running the tool, not by asking the Owner**. (This is the read-only REVIEW gate only: the **execution gate** — per-write Owner authorization at a live-data write — and the **push-GO** are untouched.) **At T2 it is skipped cleanly when unavailable; at T3 it is REQUIRED** (`core/WORKFLOW.md` § Steer tier table — T3 owes BOTH cross-family families), so an unavailable lens at T3 takes the substitution rule below, and if no different family can be seated, the recorded availability route governs; outside it the artifact is **not gradable at T3** → Owner, and a reduced verdict is never full. **Additive** (never replaces a mandated reviewer or the panel count), **advisory** (findings → PM triage → approved fixes re-verified; the Owner GO is final), **budget-free** (does not consume the external gate). Brackets the external gate (capstone + fix-delta bookend, per the final-gate rule). **Tradeoff** vs a same-family cold *agent*: more independent (different weights) but reasons from the supplied artifact+context; a same-family agent has live full-repo depth but shares the author's blind spots — use both when a fix is subtle. *(The runner + access are a project tool — see `core/BINDINGS.md`.)*

## External gate — the authority pass
**External gate (T2/T3, *after* cold passes).** Reviews the **code/diff + the design as a contract** — **never an advocacy ticket as the primary artifact** (a ticket of "what passed / cases pinned" anchors a false clear; the code is the artifact, the design is the contract). Reserved for this pass (conserve its budget). *(Tooling in `core/BINDINGS.md`.)* **Substitution (credits):** when a non-Claude reviewer is out of credits, the gate **does not drop that role — it substitutes the best available model and replicates missing scope/intent** (unframed, same hunt). An Owner-evidenced reduction may use the existing same-family fallback. A recorded Project-Principal decision may select an eligible replacement only when it preserves the required family floor; it is not risk acceptance or a waiver. For a required Claude seat, use the availability route below. Otherwise priority is **another *different* family first** (preserves decorrelation — Codex out → Gemini runs the cross-family role, and vice versa); only if all eligible different families are out, a **same-family free-roaming frontier pass** that replicates the role (posture preserved, decorrelation reduced). **A design-mode lens substituting into a CODE seat is bounded by transport:** it reviews designs, not diffs — a code payload over the inline envelope under-reads, so that substitution is an escape requiring the envelope or an approved slice plan (`core/GATES.md` § Routing), never an unqualified swap. The verdict **records the substitution + the decorrelation level** (full / one-family / same-family-only) — never counted as full when reduced. The **Builder-family cold panel is never substituted away** (free, always available — the spine): that is the **Claude** panel by default, and the swapped-in Builder's family under a compute-weather flip — the spine is family-relative; the shape (a fresh same-family blind panel always runs) is not.

**Required-review availability route.** Capacity, outage, or unavailable supported runtime is **no
verdict**. Keep the requested seat, complete artifact/scope, count and free posture; immediately use
supported Gemini only when its verified binding and transport cover them all, otherwise fresh cold
Astra. Never wait for reset, re-ask Owner, relax version/size/slice/tool/identity/permission controls,
or bypass host denial; substantive `NO-GO` is not unavailability. Free input is the actual change plus
contract mechanisms, criteria and invariants, with no findings, verdicts, rationale, advocacy or
narration; a later folded pass may receive history. Receipt: failed route; requested/actual seat and
family; concrete model/effort; artifact identity; pass type; packet scope; known pre-load; verdict;
and decorrelation level. Astra on a Codex build is **same-family-only**, never cross-family/full
diversity. A valid fallback discharges the seat: do not duplicate a running/completed seat or repeat it
when Claude returns; use Claude for the next appropriate unstarted seat. Existing push/deploy/live,
destructive, access/credential, new-spend, critical boundaries and T3 honesty remain.
**The mirror, on a Claude build:** an unavailable Codex seat takes the same route and receipt —
supported full-coverage Gemini first, otherwise a fresh cold Claude frontier pass recorded
**same-family-only**, never cross-family; use Codex for the next unstarted seat when it returns. A
Claude lane reaches the Codex seat through `scripts/codex-gate.sh` (`init --with-gate-runners`).
